# Student Project Checklist

Usa esta lista para comparar tu proyecto con la entrega de referencia. No necesitas crear una tienda idéntica; debes demostrar un flujo completo y coherente.

## 1. Structure

- [ ] The page uses semantic HTML.
- [ ] Navigation, headings, labels and buttons are understandable.
- [ ] CSS and JavaScript are stored in separate files.
- [ ] The browser console opens without errors.

## 2. Style

- [ ] The interface has a consistent visual hierarchy.
- [ ] Forms and buttons show visible states.
- [ ] The layout adapts to mobile and desktop screens.
- [ ] Text remains readable and elements do not overlap.

## 3. Behavior

- [ ] At least one interface section is rendered from JavaScript data.
- [ ] The project responds to user events.
- [ ] User input is validated before processing.
- [ ] The page displays a clear result or output.
- [ ] The user can correct or reset the process.

## 4. State and evidence

- [ ] Important data is represented with arrays or objects.
- [ ] State changes are centralized and predictable.
- [ ] Relevant information survives a page reload with `localStorage`.
- [ ] The project includes a README with run instructions.
- [ ] Commits describe meaningful progress.
- [ ] The final version is available from the official repository.

## Minimum class target

Before the end of the session, complete one improvement that is visible in the interface and supported by code: a validation, dynamic render, state update, persistent value, responsive correction or test.
